# persona-detail 变更记录

## v1.2.3（2026-11-10）

图书馆要能查账：借了几本、借错了没有。

- **借阅台账 `query-log.json`**（落在存档目录，跟 `store.json` 同层，滚动保留最近 100 条）：每条记时间、查询词、分类、命中条数、命中的 id、是否查空、会话。查档案失败不影响查询本身（写台账出错只记日志）。
- **新路由 `GET /api/persona-detail/queries`**：返回总次数、查空次数、最近 N 条记录，以及「一直是查空、可能该补的词」排行（按查询词聚合，取前 8）。
- **面板「借阅记录」区块**：时间 + 查的词 + 命中几条 + 借到哪几号；顶部列出反复查空的词，直接看出档案缺什么。
- **面板「模拟提问」区块**：输入一句话走真实检索，先看会借到哪几条、命中正文长什么样、推断条目带不带软化提示，再决定要不要改条目。整句会自动剔掉「你/我/的/吗/几号/什么」等词拆成名词（`used` 里能看到实际拿去查的词），避免拿整句去查白跑一趟。模拟不写台账（`opts.silent`），不会污染真实借阅记录。
- **借书数量收紧**：命中结果按相对阈值过滤——只保留分数达到最佳命中 50%（且不低于 4 分）的条目，勉强沾边的留在架子上。实测查「deepseek」不再把正文里偶然出现该词的 #33 服装一起借出来。
- **单条正文超 160 字截断**（带 `truncated: true`），防止将来长条目一次性把上下文占满。
- 路由 11 → 13 条。

## v1.2.2（2026-11-09）

挡「机器改得太主观」：来源可查 + 主人签字。

- **每条条目带 `source`**：`角色卡原文` / `聊天记录` / `主人手写` / `推断`（也接受 `roleText`、`chat`、`owner`、`inferred` 及自由文本）。面板列表按来源着色，`推断` 标红；查询结果也回传 source。
- **整理结果不直接入库**：`manage_persona_detail action=import` 默认写进待确认队列 `staging.json`（同标题同正文自动去重），返回 `staged` / `pending`，不再返回 `added`。主人明确说「直接入库」时才加 `direct=true` 跳过。
- **面板「待确认」区块**：逐条「入库 / 丢弃」、顶部「全部入库 / 全部丢弃」；入库走真正的写盘流程（写前自动备份档案），被拒的条目退回队列不丢。
- 新路由：`GET /api/persona-detail/staging`、`POST /api/persona-detail/staging`（`{action:'accept'|'reject', ids?}`）。
- 面板编辑器新增「来源」输入框（下拉建议四种）；面板批量导入仍是主人手动粘贴，默认直接入库（`direct` 默认 true）。
- `bootstrap_persona_detail` 的 rules 增加来源要求：`inferred` 最多 3 条、不许编新事实；返回里带 `pending` 队列长度。
- **存档目录兜底**：每次解析到自定义目录就记一份 `DATA_DIR/persona-detail/storeDir.hint`。刚启动/刚热重载、技能配置还没读到时用 hint 顶住，否则会算回默认目录、在数据目录里另建一份空档案（旧档案看起来「空了」）。主人主动把「存档目录」清空时仍按清空处理，不会被 hint 拉住。
- `setup` 建档案时若算回默认目录而 hint 明明指向别处，跳过建档并记日志，绝不另建。
- **技能默认值不再带本机信息**：`settings.adminQq` 与 `settings.storeDir` 默认为空。发给别人装，档案落他本机的 QQ Agent 数据目录，管理员自己填；不会把打包者的桌面路径和 QQ 号带过去。
- `ensureStore` 连带预建 `staging.json` 空骨架，装好打开目录就能看到两个文件。
- 面板「来源」输入框的 label 精简为「可空」，四种取值靠 placeholder 与下拉提示，不再挤成两行。
- **编号打错不再静默成功**：`POST /api/persona-detail/staging` 给了 `ids` 但一条都匹配不上时，返回 400 +「队列里没有编号 XX 的条目，可能已被入库或丢弃了，刷新一下面板再看」，并把不存在的编号放在 `missing` 里；入库/丢弃都按 `ok` 决定状态码。部分匹配时其余条目照常成功、`missing` 一并返回，前端额外提示一句。
- **检索不再被巧合撞词骗到**：`scoreEntry` 现在区分强弱证据，只有标题/关键词命中（或 ≥4 字的词命中正文、或多个词命中）才算数，纯正文里撞上短词的弱命中丢弃。起因是实测查「生日」把「围裙口袋…带大学**生日**常感」那条捞了出来；修完「生日」只返回 #35。代价是只靠正文出现的单关键词会漏（如问「弟弟」捞不到 #3 转生化形），提示词里已要求模型查不到就换词再查。
- **提示词按「被动图书馆」重写**：明确不主动讲、不主动提、正常聊天里别往外倒设定；只有被问到或聊天里出现、且角色卡确实没有的东西才调 `query_persona_detail`；角色卡已写明的（姓名、身份、性格行为规则、喜好、讨厌、输出规范、禁令）不用查。`QUERY_TOOL` / `MANAGE_TOOL` 的 description 同步（后者补 source 要求、import 默认进队列但 `direct=true` 可直写）。
- **查询返回自带使用说明，挡住两种出戏**：命中时带 `hint`（只用角色口吻说一两句、别念条目别列清单、别提「档案/设定/资料库」）；查不到时带 `nothing: true` + 提示用角色口气搪塞（「这事儿我哪记得」），并明令不许说「我的档案里没有」「我刚查过档案」。档案 0 条时不只说查不到，而是提示「有机会让主人整理一次人设」并指向 `bootstrap_persona_detail`——装到新机器能自己接着长。
- **推断条目在使用侧也降级**：`source=推断` 的条目返回时附 `note`「这条是推测出来的，不是确定事实，说的时候带『好像是』『大概』」。入库侧有审批，使用侧也不许当事实讲。

## v1.2.1（2026-11-09）

补「原来人设不能丢」这一条：改动前留带时间戳的备份，面板点按钮就能退回。

- **人设备份 `persona-backup-YYYYMMDD-HHMMSS-xxxx.json`**：存角色卡 `roleText` 全文 + 人设模板列表（`customPersonas`），落在存档目录（和 `store.json` 同一个文件夹）。触发点：调 `bootstrap_persona_detail` 整理人设前自动备份一次；面板「备份当前人设」手动备份。
- **档案备份 `store-backup-*`**：导入前、删除条目前自动备份整份档案；面板「备份当前档案」手动备份。
- **回退接口** `POST /api/persona-detail/restore`：`type=persona` 恢复角色卡 + 模板列表（走 `updateConfig`，内存与磁盘一起改），`type=store` 覆盖整个档案。**回退前会先给当前版本再做一份保险备份**，退错了还能回来。
- 面板新增「备份与回退」区块：两个页签（人设备份 / 档案备份），每行显示时间、字数/条数、原因，带「退回」按钮；顶部两个手动备份按钮。
- 备份保留最近 30 份，超出自动删最旧。
- 版本 1.2.1，热重载生效。

## v1.2.0（2026-11-09）

按「插件要能分发给别人」的要求补三件事：包里不带原主人的数据、装好能自己长出来、主人能直接调试。

- **档案文件自动创建**：`setup()` 里调 `ensureStore()`——存档目录没有 `store.json` 就建空骨架 `{version:1, entries:[]}` 并记日志。装到新机器不会再出现「文件夹空着、以为没装上」。
- **自举工具 `bootstrap_persona_detail`**（管理员专用）：返回角色卡 roleText 全文 + 「该拆进档案 / 该留在角色卡」+ 现有分类 + 目标条数，模型据此整理。
- **`manage_persona_detail` 增加 `action=import`**：`entries` 传数组或 JSON 字符串，`mode=append|replace`，逐条校验标题/正文/单条字数/总数上限，返回写入条数与跳过原因。
- **管理面板 `/api/persona-detail/ui`**：自带 `admin.html`，经 `api.registerPluginRoutes` 注册 6 条路由（条目列表、保存、删除、批量导入、导出 store.json、页面本身）。支持搜索、按分类筛选、点选编辑，保存即写盘（写前留 `store.json.bak`）。
- 系统提示词指引补一句：档案为空或主人说「整理人设」时，先调 `bootstrap_persona_detail`，再用 `import` 写入。
- 设置页 `storeDir` 的描述里带上管理面板地址，免得入口没人知道。

- `index.js` → `QUERY_TOOL.description`：补「外形长相、生日」；`query` 参数示例增加「头发 围裙」。
