# 0.4 扩展兼容范围

0.4 的插件、技能在安装目录中保留原包。0.5 按账号读取独立的设置和开关，为每次加载创建单独的模块副本。无需修改清单或手工改写市场包。

`apiVersion: 1` 同时出现在两代扩展中，不能仅凭此字段判定兼容。加载器先保留目录类型，再根据真实调用接入 `bundled/compat-04` 的 SDK 与模块适配。

## 接回的旧接口

| 旧接口 | 当前行为 |
| --- | --- |
| `api.config()`、旧工具参数顺序与 `parameters` | 映射到该扩展自己的 SDK 设置和工具定义；现代 `params` 定义保留现代调用顺序 |
| `src/config.js` 的 `DATA_DIR` | 当前账号的 `data/plugins/<id>/legacy-host/`；不指向其他账号或程序安装目录 |
| `getConfig()` | 仅提供该扩展的开关、设置与非密钥的 `api.maxRounds`；不提供模型密钥和全局配置写入 |
| `src/skills/config.js` | 读取自身配置，拒绝通过此模块读写其他扩展或切换其他扩展的开关 |
| `src/thinking.js` 的三个参数辅助方法 | 按需委托当前 `llm.dialect` 提供者；未启用提供者时给出明确错误，兼容插件本身仍可独立加载 |
| `src/onebot.js` 的表情方法包装 | 在本代独立的替身客户端上执行，只接收图片段的 `sub_type` 显示标记；不修改真实客户端的原型，不新建连接 |

表情适配只作用于发送队列的表情路径，普通图片与文字不受影响。既有 `sub_type` 不被覆盖；增加消息、替换正文/文件或异步重发均不在此适配范围。停用或代码指纹变化后不再使用该代转换。

第一次读取旧数据目录时，复制当前账号下以扩展 ID 命名的旧资料目录；`life-memory` 还识别旧 `life-events` 目录。已有新资料优先，旧资料不删除。复制记录保存在该账号扩展目录中，重载不反复复活已经清除的旧记录。其他非标准目录需要专门的数据迁移适配，不能直接假定已搬迁。

## 明确拒绝的情况

| 错误代码 | 含义和处理 |
| --- | --- |
| `COMPAT04_HOST_VERSION_RESTRICTED` | 原包自检仅允许 0.4。保留失败状态，不伪造宿主版本或检查结果 |
| `COMPAT04_PRIVATE_IMPORT_UNSUPPORTED` | 仍引用未适配的旧私有模块，如旧 `ChatStore`；需要补充对应接口适配 |
| `COMPAT04_HOST_PATCH_UNSUPPORTED` | 尝试改写宿主界面、启动代码或兼容模块。UI 和 Electron 路径已从真实宿主链接中断开；检测到加载期间的改写后拒绝激活 |
| `EXTENSION_DEPENDENCY_MISSING` | 缺少或未启用能力提供插件。`command.dispatch` 来自旧指令前置扩展，不能用一个空实现代替实际分发 |
| `COMPAT04_GLOBAL_WRITE` / `COMPAT04_CONFIG_WRITE` | 旧包直接写全局配置，需要改为受控的 SDK 操作 |

扩展市场审核、成功复制安装目录、卡片显示已加载，都不能单独证明业务功能兼容。验证应包括真实调用链、提示词内容、开关、重载、账号隔离和资料保留。

导入副本与 SDK 权限不构成任意 Node.js 代码的系统级沙箱；仍应只运行可信扩展。本文中的隔离路径用于避免旧接口误写共享宿主与串账号，不是恶意代码隔离保证。

回归入口：`node test/run-m4.mjs`，其中包含 `test/compat04-host-modules-test.mjs`。市场原包实测应另用禁止真实 QQ、私人文件、原生网络及子进程的专用测试宿主。
