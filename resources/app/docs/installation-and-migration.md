# 0.5 独立安装与旧版资料复制

安装器允许选择目录。新目录必须为空，并且不能与检测到的旧版目录相同、重叠或互相包含。0.5 使用独立的 Windows 安装记录和“QQ Agent 0.5”快捷方式；已有本安装器版本时拒绝重复覆盖，可使用应用内更新。安装过程不调用旧版卸载程序。

安装器从当前用户及本机的卸载记录、常见程序目录和旧版 AppData 中识别 QQ Agent 0.4/0.5。复制页默认选中检测到的旧版，也可以选择其它旧版程序文件夹；便携版可以手动指定。取消勾选可进行全新安装。安装前需要退出正在运行的旧版及其协议端，确保源文件没有继续写入。

程序文件放在新安装目录，用户文件对应如下：

| 旧版内容 | 0.5 位置 |
| --- | --- |
| 主用户数据目录 | `data-v05/` |
| `data-2/` 等独立工作区 | `data-v05-2/` 等 |
| 用户插件、技能、可信组合 | `extensions/plugins/`、`extensions/skills/`、`extensions/overrides/` |
| 已有独立协议端目录 | `protocols/` |
| 早期 `snowluma/`、`napcat/` | `protocols/SnowLuma/`、`protocols/NapCatQQ/` |
| 0.4 安装版 `resources/app/protocols/` | `protocols/` |
| 0.4 安装版 `resources/app/snowluma/`、`resources/app/napcat/` | `protocols/SnowLuma/`、`protocols/NapCatQQ/` |

账号配置、聊天、成员记忆、会话、用量、表情、提醒、扩展私有数据和多账号数据随用户数据一起复制。0.4 配置通过现有兼容迁移器转换；0.5 按原有格式复制。受控的本地文件路径改指新目录，聊天文字及记忆正文保持原样。进程锁、浏览器缓存和临时文件不会导入。

协议端按完整目录复制，保留 ZIP、已解压程序、令牌配置及登录数据库；本步骤不启动协议端。若同时检测到多个相互冲突的存储目录，安装会停止并保留源目录，避免任选一份或覆盖凭据。

插件与技能共用安装目录；各账号的启用状态、设置、宿主存储及旧扩展的 `./data` 分别保存。首次启动时归并旧账号目录中的扩展并保留原目录；已有开关与设置保留，新账号或其它账号首次看到的共享扩展默认停用。同名代码不一致时保留当前共享版本，记录冲突并保留原包。安装、更新和卸载会同步到各账号；卸载对全部账号生效，私有存储保留。

复制在新目录的随机暂存区完成，并核对文件摘要和源目录是否变化。内容冲突、链接、源文件变化或复制失败均停止提交，不卸载或修改旧版；不会自动运行导入的插件、协议端或新应用。安装后的首次启动通过安装记录定位数据，不再从其它目录隐式导入。

静默安装支持 `/SOURCE=旧版程序目录` 指定来源，或 `/NOMIGRATE` 全新安装；NSIS 的 `/D=新目录` 必须放在命令行最后。正常图形安装直接选择即可。

安装检查失败会显示独立错误编号、实际路径和对应处理方法，不再把所有情况都归为“目录非空或旧版未退出”。目录非空时最多列出 5 个已有名称（包括隐藏文件）；旧版运行时显示进程名称和 PID。诊断只包含本机路径、文件名及进程信息，不读取展示账号配置、令牌或聊天内容。

在“复制旧版资料”页点击下一步时先检查，失败后可以返回修改目录或关闭旧版后重试；进入安装前会再检查一次，防止期间目录内容变化。安装器不会为了通过检查而删除已有文件或强制终止进程。

| 错误编号 | 含义 |
| --- | --- |
| `TARGET_NOT_EMPTY` / `TARGET_NOT_DIRECTORY` | 新目录有内容（可能是安装包、隐藏文件或残留），或选中了文件 |
| `TARGET_OVERLAP` | 新旧目录相同或互相包含 |
| `INSTALL_ALREADY_REGISTERED` | 已有同一 0.5 安装器的 Windows 安装记录，与 0.4 是否运行无关 |
| `SOURCE_RUNNING` | 通过程序实际路径检测到旧版/协议端进程 |
| `SOURCE_LOCK_ACTIVE` | 旧锁记录指向存活 PID，但不能确认其是否仍是旧版；区分后台运行与过期锁，避免误报为已确认运行 |
| `SOURCE_NOT_FOUND` / `SOURCE_INVALID` | 旧目录不存在、选错了目录，或版本文件损坏 |
| `PATH_INVALID` / `PATH_DRIVE_ROOT` / `PATH_LINK` | 无效路径、磁盘根目录或目录链接 |
| `PROCESS_CHECK_FAILED` | Windows 无法完成进程检查；不等于已发现运行中的旧版 |
| `ACCESS_DENIED` / `FILE_BUSY` / `DISK_FULL` / `PATH_TOO_LONG` | 权限/占用/磁盘空间/路径长度问题 |
| `SOURCE_CHANGED` / `COPY_VERIFY_FAILED` | 源文件仍在变化，或副本校验失败，停止提交 |
| `DATA_LAYOUT_CONFLICT` / `DATA_CONVERSION_FAILED` | 多套资料目录冲突，或 0.4 转换失败 |
| `TARGET_CHANGED` / `PLAN_INVALID` | 检查后目标变化，或安装临时计划无效 |
| `PRECHECK_FAILED` / `DETECTION_FAILED` / `MIGRATION_FAILED` / `HELPER_FAILED` | 未能进一步分类的检查、复制或辅助程序错误，保留编号及截图排查 |

# 分发副本与隐私

`npm run release:prepare` 在独立临时分发目录中按明确清单收集程序及生产依赖，并执行隐私检查。开发者本机的 `data/`、账号、聊天、浏览器状态、截图、验收文件、协议端发行包及安装的用户扩展不进入安装包。文档示例中的个人 Windows 用户目录改成通用示例；公开项目网址、开源许可证和公开署名保留。开发者的本地运行数据保持原位。

准备命令输出 `builder.json` 的路径；使用该配置调用 electron-builder 构建。安装包仅随程序提供协议适配代码，不内置 NapCat 或 SnowLuma 发行包。
