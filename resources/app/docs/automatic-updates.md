# QQA 应用自动更新

适用于 Windows 发行版。插件和技能的在线更新仍使用各自原有流程。

## 用户操作

打开 QQA 后及每小时检查一次版本；也可以在「设置 → 应用」手动检查。发现可验证的新版后弹出浮窗，点击「下载更新」立即下载并校验，期间继续使用当前版本，不退出账号、不启动安装。

下载完成后询问是否现在安装。点击「立即安装」才会保存设置、退出 QQA 及其管理的账号和协议进程、备份、替换程序并自动重启，无需再点击安装向导。安装前再次校验下载缓存，损坏文件不会用于替换旧程序。

点击「稍后」则在右下角留下安装图标；点击图标会再次询问，未确认不会安装。下载文件和稍后选择会跨页面刷新、应用重启保留，可以离线安装，且不会重复下载。下载和安装准备阶段可以取消；开始退出和安装后等待完成。

保留所有账号配置、聊天记录、协议端文件及配置、用户安装的插件和技能、扩展数据和 overrides。自动更新不运行卸载程序，不重新创建快捷方式，不修改开机启动项。程序目录之外的当前数据目录、协议目录和扩展目录也会备份。程序退出失败时不会开始替换文件。

新版必须返回本次启动凭据、实际版本和进程号；桌面版还需成功加载界面。启动崩溃、超时、替换失败会恢复旧程序及更新前的数据快照，再启动旧版。重新打开页面后提示实际更新或恢复结果，不把失败显示为完成。

## 支持范围

- Windows x64/arm64 桌面发行目录（`asar: false`）及独立 Node.js 运行时启动的源码发行目录。每个平台、架构和发行类型必须分别提供更新包。
- Git 开发目录拒绝自动替换，保护尚未提交的修改。源码版的 Node.js 必须放在安装目录之外。
- 安装目录需要当前用户具有写入权限。受保护目录会提示重新以具备写入权限的用户启动；不会静默申请管理员权限。
- 同一个安装目录一次只允许一个更新任务。其他独立 QQA 实例还在使用该程序时，先关闭它们。多账号工作进程由主窗口统一退出、恢复。
- 安装过程中再次打开 QQA 会被拦下，避免用尚未替换完整的程序访问账号数据；更新助手启动的本次验证进程可以正常进入。仅下载完、尚未确认安装的缓存不会阻止正常启动。
- 签名缺失、错误、平台不符或旧格式版本清单，只保留手动下载入口，不执行远程程序。

## 发布新版

自动更新需要**带签名的清单与专用 ZIP**，不能只修改版本数字或直接使用 NSIS 安装程序。清单仍放在 `https://kondius.cn/qq-agent/version.json`，保留 `version/url/notes` 字段供旧客户端查看。

### 向 0.4 用户发布 0.5 安装包

0.4 读取同一清单的 `version/url/notes`，启动后及每小时检查一次。它通过 `url` 打开下载页，不执行 0.5 的自动安装流程。首次迁移发布使用 `0.5.0` 即可。

下载选择页源码位于 `website/qq-agent/download/`，提供天翼云盘、百度网盘、夸克网盘及提取码复制；无 JavaScript 时链接和提取码仍可使用。发布时先上传并验证页面及资源，再将 `website/qq-agent/version.json` 发布到线上，最后核对两个域名的清单响应。旧版用户下载后退出旧程序及协议端，安装到空的新目录，并选择复制旧版资料。

官网当前保留旧站关闭规则；下载页仅开放自身及 CSS/JS，不应为下载页重新开放整个旧站。后续更换安装包时须同步更新页面版本、文件名、大小、SHA-256 和三个网盘地址。此手动迁移清单不构成可自动安装的签名更新包；后续 0.5 客户端自动更新仍使用下述签名发布流程。

首次设置签名密钥（只做一次；已有密钥会拒绝覆盖）：

```powershell
npm run update:key -- --private .qa-local/app-release-signing/update.private.pem --public assets/update-public-key.pem
```

私钥只在发布机器保存，另行离线备份；不上传到 GitHub、服务器、安装包。公钥随客户端分发。当前工作区已生成这对密钥；不要再次生成来替换它。

发布时先调整 `package.json` 和锁文件的版本，生成干净的发行目录。以下以 `0.5.1` 为例：

```powershell
npm run build:dir
npm run update:pack -- --input dist/win-unpacked --kind desktop --arch x64 --out dist/releases/0.5.1/qqa-0.5.1-win-x64.zip --manifest dist/releases/0.5.1/version.json --key .qa-local/app-release-signing/update.private.pem --base-url https://kondius.cn/qq-agent/releases/0.5.1/ --notes docs/release-notes.txt
```

如果也分发源码包，对**含所需生产依赖的干净源码发行目录**再运行 `update:pack --kind source`；复用同一版本的 `--manifest` 路径，会合并包列表并重新签名。不是直接打包正在开发的工作区。发布工具仅收集允许替换的程序文件，不打包根目录的账号数据、protocols、用户 plugins、skills 或 overrides。

先上传完整 ZIP，核对远端字节数和 SHA256；最后原子替换 `version.json` 并刷新其缓存。已经发布的版本 ZIP 使用不可变地址，不能原地替换其内容。清单每一处修改（包括下载地址、说明、大小、版本）都要重新签名。不要上传测试清单，以免通知真实客户端。

旧客户端没有本更新器和公钥，仍需手动安装一次包含此功能的正式版；之后使用本流程。升级签名公钥需要额外的密钥迁移发布，不能直接用另一对密钥替换现有密钥。

## 更新文件与恢复

每个安装目录的工作文件位于 `%LOCALAPPDATA%/QQAgentUpdates/<安装目录标识>/<任务号>/`，包含下载文件、阶段状态、安装日志和 `backup/` 恢复副本。`last.json` 指向最后任务；安装锁按安装目录共享，不随 QQ 账号变化。

安装包只替换白名单内的程序单元；拒绝目录越界、链接、Windows 文件别名、重复路径、超限解压和用户数据覆盖。复制前后对文件散列复核，数据备份成功后才替换程序。运行缓存 `data-plugin-runtime` 会保留，但不作为可恢复用户数据遍历。

任务结束后保留恢复副本，确认正常使用后可关闭 QQA 再清理旧的任务目录。不要在更新进行时删除暂存文件。

突然断电或系统强行结束更新助手无法依靠仍在运行的进程恢复。恢复副本和日志仍留在上述目录；确认该安装目录的 QQA 已全部退出后，可使用该任务自带的助手恢复：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<任务目录>/apply-update.ps1" -Action Recover -Job "<任务目录>/job.json"
```

若磁盘损坏、备份文件被改动或恢复时文件持续被锁定，界面明确提示自动恢复未完成并保留恢复副本位置，不宣称已恢复成功。

## 验证

```powershell
npm run test:update
$env:QQA_TEST_DESKTOP_UPDATE='1'
node --test-name-pattern='real packaged Electron' test/app-update-native-test.mjs
```

测试使用独立临时安装、合成账号及测试签名密钥；不替换当前工作区、不使用真实 QQ，不修改线上清单。覆盖通知点击仅下载、二次确认才安装、稍后图标、跨应用重启保留缓存且只下载一次、真实原生更新助手、真实 Electron 更新/回滚、数据保留、损坏下载和缓存、恶意 ZIP、未确认/过期确认、取消、并发任务、界面及认证边界。
