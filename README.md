QQ Agent 是一套「薄内核 + 全插件」架构的 QQ 机器人桌面端：Electron 外壳负责界面与控制台，内核负责会话调度、提示词组装与插件加载，具体能力（记忆、表情、群聊分寸、链接解析等）全部由 `extensions/` 下的插件与技能提供。

本仓库是 **0.5.1 版本的源码快照**，只保留可读、可改的代码部分：

- 仓库内包含：内核 `resources/app` 的 `src / ui / bundled / plugins / skills / overrides / docs / examples / scripts`，以及 `extensions` 下的全部插件与技能
- 仓库内不包含：Electron 运行时二进制（`QQ Agent.exe`、`*.dll`、`*.pak`）、`node_modules`、OneBot 协议端的程序与配置、任何账号 / 密钥 / 令牌 / 聊天记录 / 记忆库 / 表情库 / 日志。**clone 下来的目录不能直接双击运行**；可运行的整包见 Releases 页 `v0.5.1-dfy.1`（说明见下方「运行方式」）
- 文中出现的 `1000000000`、`2000000000` 一类号码均为占位值，不是真实账号

## 运行方式

**便携包已提供。** Releases 页 `v0.5.1-dfy.1` 下挂有 `QQAgent-0.5.1-win64-portable-20261126.zip`：Windows x64，162,252,835 字节（154.74 MiB），SHA256 `809d872ebd0b877e209d889a3278effdb6d8257a9d95e77fef73aebb90aa932a`。解压即用，不需要安装器；包内已剥离 `data-v05`、`config`、`logs`、`*.bak` 与 OneBot 协议端。

本仓库本身仍然只有源码：`resources/app` 与 `extensions` 的 JS/JSON/HTML，不含 Electron 运行时与 `node_modules`，**所以 clone 下来不能直接双击运行**。

要拿到可运行的客户端，有两种方式：

1. **直接下载便携包**：从 Releases 下 `v0.5.1-dfy.1` 的附件解压到短路径，双击 `启动.cmd`。下面的步骤就适用
2. **自行组装**：Electron 运行时 + 本仓库的 `resources/app`，在 `resources/app` 下补 `npm install --omit=dev` 生成 `node_modules`；或者拿已有的同版本安装目录，把本仓库的 `resources/app` 与 `extensions/` 覆盖进去，这是最快的替代法

下面的步骤适用于**已经拿到整包**之后（无论是别人传给你的，还是你自行组装的同结构目录）：

1. 解压到短路径，例如 `D:\QQAgent`（不要放 `C:\Program Files`，那里没有写权限，数据写不进去）
2. 双击 `启动.cmd`，或直接双击 `QQ Agent.exe`
3. 控制台出现 `控制台：http://127.0.0.1:3210/` 后，浏览器打开该地址即可
4. 连 QQ 需自备 OneBot v11 协议端（NapCat / LLOneBot 一类，需先装官方 QQ NT）。协议端不在仓库与发布包内：那属于第三方注入工具，不在本项目授权范围内，也不适合随包分发。协议端没起来时面板照样能开、插件照样能加载，只是发不出消息

整包里剥掉了 `data-v05` 个人数据、`config`（含 token 与账号）、`logs` 与全部 `*.bak`，首次启动会在包内新建空的数据目录。首次开机要填的必填项见下方「首次配置必填项」。

想改插件就用这份源码：`extensions/plugins/<id>/index.js` 改完在面板里重启该插件即可；改内核则改 `resources/app/src`，用发布的 `resources/app` 整目录替换。

## 目录结构

完整文件树（656 个源码/配置文件、逐目录体积）见 [`目录结构.md`](目录结构.md)；可折叠、可搜索的浏览器版见 [`仓库目录可视化.html`](仓库目录可视化.html)（下载后用浏览器打开，离线可用）。统计口径排除这两份自生成文档本身，故 Git 树上共 658 个文件。

```
.
├─ resources/app/           内核源码（对应安装根 resources\app）
│  ├─ src/                  主进程、控制台路由、提示词、技能加载
│  ├─ ui/                   控制台前端（面板、外壳、组件）
│  ├─ bundled/              内置能力（OneBot 传输层、兼容层、市场等）
│  ├─ plugins/              随包内置的插件副本（带 _1 后缀）
│  ├─ skills/               随包内置的技能副本
│  ├─ overrides/            组合层覆盖补丁（persona-detail 管理面板）
│  ├─ docs/ examples/ scripts/
│  └─ package.json
└─ extensions/
   ├─ plugins/              14 个插件（实际启用位置）
   └─ skills/               3 个技能
```

### 插件的来源与二次开发

表里没有一个是「原版原样」的插件，全部经过二次开发，别拿它和市场版对照着用：

- **起步来源**：多数插件最早是从原作者 Kondius 的「插件市场」下载的版本，作为起点；另一部分（`bili-video`、`xhh-post`、`dfy-chronicle` 等）直接在本地从零写的。粗略分辨法：看 `plugin.json` 的 `author`，写「本机定制 / 本地自建 / 为 QQ Agent 定制」的基本是自建或大改。
- **版本已经跑偏**：这些插件是长期在本机群聊里按真实反馈迭代出来的，版本号和功能都远超市场版（如 `memory-plus` 2.12.1、`sticker-steal` 5.5.8、`topic-ledger` 1.3.3）。不少插件的原始行为被整段替换，配置项、数据结构、提示词注入方式都与市场版不同，**不保证兼容**，旧插件目录请整目录替换而不是挑文件覆盖。
- **融合了别处的思路**：分层记忆 + 按需检索、话题台账与收尾、好感度与关系网、抑制 AI 腔、前缀缓存稳定化等做法，参考了若干开源项目与同类机器人的实现，再按本机场景重写；思路可以借鉴，代码以本仓库为准。
- **欢迎反馈**：觉得某处有更省 token / 更稳的实现思路，或有功能建议、兼容问题，欢迎开 Issue（附插件版本号 + 相关日志片段最有效）。若有更好的方案，会直接改进来。

## 本地运行

本仓库不含运行时，需要一份已安装好的 QQ Agent 0.5.1 宿主（Electron 壳 + 协议端）：

1. 插件：把 `extensions/plugins/*`、`extensions/skills/*` 放进安装根的 `extensions/` 对应目录，重启宿主或在控制台「技能」页点重载。
2. 内核：把 `resources/app` 覆盖到安装根的 `resources\app`（覆盖前先备份），再执行 `npm install --omit=dev` 补齐依赖。
3. 宿主要求 Node.js ≥ 20（`resources/app/package.json` 的 `engines`）。
4. 协议端（OneBot）由宿主按自身设置拉起，不在本仓库内。

## 发布包（核心 / 插件分包）

便携包拆成三类附件：核心包、插件合集包、每个插件的单独小包。插件迭代时只重传小的那些，150 MB 的核心包不用动：

| 附件 | 大小（约） | 装什么 | 什么时候需要更新 |
|---|---|---|---|
| `QQAgent-0.5.1-dfy-win64-core-YYYYMMDD.zip` | 158 MB | Electron 运行时 + `resources/`（内核与内置能力），不含 `extensions/plugins`、`extensions/skills` | 只有换内核版本、换运行时才重打 |
| `QQAgent-0.5.1-dfy-extensions-YYYYMMDD.zip` | 4~5 MB | `extensions/plugins`（14 个插件）+ `extensions/skills`（3 个技能） | 每次改插件就重打这一个 |

安装顺序：先解压核心包到一个目录，再把插件包解压到**同一目录**（包内已保留 `extensions/` 层级，直接覆盖即可）。两者都不含协议端、账号、聊天记录与任何个人数据。

### 单插件包

每个插件另有一个独立小包，只更新某一个插件时不必拿整个插件合集：

| 附件命名 | 大小 | 说明 |
|---|---|---|
| `QQAgent-dfy-plugin-<插件名>-<版本>-YYYYMMDD.zip` | 4 KB ~ 4.2 MB | 只含 `extensions/plugins/<插件名>/`，解压到客户端根目录覆盖同名目录，重启或控制台热重载即可 |

单包体积差异主要来自资源文件（`dfy-chronicle` 带一张 4 MB 的长图，其余多在 100 KB 以内）。Release 正文里有逐包的版本与大小清单。

重打命令（仓库自带脚本，插件包几秒就好）：

```powershell
pwsh tools/pack-split.ps1 -Only plugins   # 日常：只重打插件合集包
pwsh tools/pack-split.ps1 -Only single    # 只重打 14 个单插件小包（输出到 release-split/plugins/）
pwsh tools/pack-split.ps1 -Only core      # 换内核时才用（需 -CoreSrc 指向解包好的客户端目录）
pwsh tools/pack-split.ps1                 # 三样都打
```
